# 每日信息推送

把你关心的网站公告和微信公众号文章，每天早晚各汇总一次，推送到企业微信群。

- 跑在 GitHub Actions 上：不需要你有一台开着的电脑，也不需要懂运维
- 零成本：GitHub Actions 对公开仓库完全免费
- 自动去重：同一条内容不会推第二次
- 故障自报：某个源失效了会主动告诉你，不会悄悄哑掉

---

## 一、十分钟上手

### 第 1 步：拿到企业微信群机器人的 Webhook 地址

**先记住判断标准，避免找错地方**：

```
正确的 Webhook 地址一定长这样：
https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=693a91f6-7xxx-4bc4-97a0-xxxxxxxxxxxx
```

域名必须是 `qyapi.weixin.qq.com`，末尾必须有 `?key=` 加一串字符。
**任何不以 `qyapi.weixin.qq.com/cgi-bin/webhook/send?key=` 开头的链接都不是 Webhook**，
尤其是管理后台里形如 `work.weixin.qq.com/wework_admin/.../openBotProfile/...` 的"机器人资料页"链接——那是给别人查看机器人简介用的，不是推送地址。

**获取步骤（建议用电脑端，屏幕大看得清）**：

1. 打开**企业微信**电脑客户端（没有就装一个，个人也能注册，不需要公司资质）
2. 进入你要接收推送的那个群
3. 点群聊右上角 `...`
4. 选 `添加群机器人` → `新建机器人`
5. 起个名字，比如"每日简报"，头像随意
6. 点确定后，**创建成功的页面上就会显示 Webhook 地址**，立刻复制保存

**手机端**：群聊右上角 `...` → `群机器人` → `添加机器人`，流程相同。

**关掉了页面怎么找回**：在群成员列表里点（或长按）机器人的头像 → `查看资料`，资料卡里能再次看到 Webhook 地址。

**这一步有个坑，请务必照做**：

创建机器人时页面下方有"安全设置"三项——`自定义关键词`、`加签`、`IP 段白名单`。
**三项都不要勾选**。

- 勾了 `IP 段白名单` 会直接推送失败：GitHub Actions 的服务器 IP 是随机变动的，无法加入白名单
- 勾了 `加签` 也会失败：本程序未实现签名计算
- 勾了 `自定义关键词` 会导致不含关键词的消息被丢弃

> 这个地址等同于密码。**任何拿到它的人都能往你的群里发消息**。只能填到下面的 Secrets 里，不要发给别人，不要写进配置文件，也不要贴到公开的地方。如果不小心泄露了，在群里删掉这个机器人重新建一个即可。

### 第 2 步：注册 GitHub 并创建仓库

1. 打开 github.com 注册账号（免费）
2. 右上角 `+` → New repository
3. 仓库名随便，比如 `daily-digest`
4. 可见性选 **Public（公开）**——公开仓库的 Actions 完全免费且不限时；私有仓库有每月额度限制
5. 勾选 "Add a README file"，然后创建

> 选公开仓库意味着别人能看到你的源清单。如果你在意，可以选私有（本项目的用量在免费额度内也够），或者把源地址写成 `${MY_URL}` 形式、真实地址放在 Secrets 里（见文末"隐私"一节）。

### 第 3 步：上传这些文件

在仓库页面点 `Add file` → `Upload files`，把整个 `feed-push` 目录里的文件**按原目录结构**拖进去：

```
.github/workflows/daily.yml
config/sources.yaml
data/state.json
src/__init__.py
src/config.py
src/dedupe.py
src/fetchers.py
src/main.py
src/notifier.py
src/store.py
src/summarizer.py
requirements.txt
```

GitHub 网页上传不支持空目录，但只要你逐个文件拖进去，目录会自动生成。

### 第 4 步：填写密钥（Secrets）

仓库页面 → `Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| Name | 必填 | 填什么 |
|---|---|---|
| `WECOM_WEBHOOK` | 是 | 第 1 步复制的机器人 Webhook 地址 |
| `LLM_API_KEY` | 否 | 大模型接口的 Key，用于生成一句话摘要。不填就只推标题 |
| `LLM_BASE_URL` | 否 | 接口地址，默认 `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 否 | 模型名，默认 `deepseek-chat` |

### 第 5 步：填写你的信息源

打开 `config/sources.yaml`，把示例替换成你真正关心的网站。怎么找源地址见下一节。

改完点 `Commit changes` 保存。

> 想在自己电脑上先验证配置对不对，不用等到 GitHub：
> `pip install -r requirements.txt` 然后 `python tests/smoke_test.py`。
> 它会检查去重、分片、报告格式和网络连通性，不需要任何密钥，也不会真发消息。

### 第 6 步：手动跑一次验证

仓库页面 → `Actions` → 左侧选 `每日信息推送` → 右侧点 `Run workflow` → 再点绿色的 `Run workflow`。

等约 1 分钟，点进去看日志。如果一切正常，你的企业微信群里会收到一条早报/晚报。

### 第 7 步：之后就不用管了

程序会在**北京时间每天 08:00 和 20:00** 自动运行。

> GitHub 的定时任务在服务器繁忙时可能延迟几分钟到几十分钟，偶尔会跳过。对于早晚报这种粗粒度需求完全够用，但不要指望它精确到秒。

## 二、怎么找到网站的信息源地址

按这个顺序找，**能用上一个就不用再往下试**：

### 方法一：RSS / Atom（最优先，最稳定）

1. 直接猜：在浏览器地址栏试 `网站域名/rss.xml`、`/feed`、`/atom.xml`、`/rss`
2. 看网页底部，很多站点有 "RSS" 或"订阅"链接
3. 看网页源代码：`Ctrl+U` 搜索 `rss` 或 `atom`，能找到 `<link type="application/rss+xml" href="...">`

找到后，在 `sources.yaml` 里写成：

```yaml
- id: my-site
  name: 某某机构公告
  type: rss
  url: https://example.com/feed.xml
  enabled: true
  keywords: []
```

### 方法二：JSON 接口（现代网站常用）

很多网页的内容是加载完再请求数据接口拿的，直接读接口比解析网页稳定得多。

1. 浏览器打开目标页面
2. 按 `F12` 打开开发者工具，切到 `Network`（网络）标签
3. 勾选 `Fetch/XHR` 过滤，刷新页面
4. 在请求列表里找一个返回内容是 JSON 的（点开看 `Response` 里有没有成堆的标题）
5. 右键这个请求 → `Copy` → `Copy link address`

然后：

```yaml
- id: my-api
  name: 某某数据接口
  type: json
  url: https://api.example.com/news?pageSize=20
  enabled: true
  items_path: data.list      # 列表在 JSON 里的位置，用点号分隔
  title_key: title           # 标题字段
  url_key: url               # 链接字段
  date_key: publishTime      # 时间字段，没有就删掉这行
  url_prefix: ""             # 如果链接是相对路径，填域名前缀
  keywords: []
```

`items_path` 怎么看：点开那个请求的 `Response`，如果看到的是
`{"data": {"list": [ {...}, {...} ]}}`，那就填 `data.list`。

### 方法三：网页抓取（前两种都没有时才用）

```yaml
- id: my-html
  name: 某某网页公告
  type: html
  url: https://example.com/announcements
  enabled: true
  item_selector: "ul.news-list li"   # 一条公告的容器
  title_selector: "a"                # 容器里标题所在的元素
  link_selector: "a"                 # 容器里链接所在的元素
  link_attr: href                    # 取元素的哪个属性当链接
  url_prefix: "https://example.com"  # 链接是相对路径时补前缀
  keywords: []
```

**怎么拿选择器**（不用写代码）：

1. 浏览器打开页面，按 `F12`
2. 点开发者工具左上角的小箭头图标
3. 用箭头点中页面上一条公告的标题
4. 在下方高亮的 HTML 代码上右键 → `Copy` → `Copy selector`

把复制出来的选择器先填进 `item_selector`。如果复制出来的太具体（带一堆 `:nth-child`），可以往上找几层父元素，选一个能同时匹配所有条目的、更短的选择器。

> 合规性：请只采集公开页面，遵守目标站点的 robots.txt，频率保持每天 1-2 次，不要绕过验证码或登录墙。本项目已设置规范的 User-Agent 与低频采集。

## 三、微信公众号接入

微信没有官方 RSS，所以这一步需要一个"转换器"。转换器输出的也是一个 RSS 地址，填进 `sources.yaml` 就能用，**主干代码不需要改**。

**重要**：GitHub Actions 是"跑完就销毁"的环境，无法长期保持微信登录态。所以转换器需要一个**常驻运行的地方**。这是整个方案里唯一需要额外资源的一环。三种选择：

### 方式 A：微信读书订阅 + 自建转换（你选的方案）

原理：微信读书 App 本身就支持关注和阅读公众号文章（官方功能），转换器复用这个通道把文章列表转成 RSS。走的是官方客户端通道，风险最低，且不限公众号。

你需要：
1. 一个**微信读书专用小号**（不要用主号）
2. 在小号的微信读书 App 里搜索并关注你要订的公众号
3. 一个常驻的地方跑转换器（开源实现如 `wewe-rss`，用 Docker 部署）：
   - 最省事：一台最便宜的云服务器，几十到几百元一年
   - 想零成本：Render / Fly.io / Koyeb 等平台的免费容器（免费层可能休眠，导致唤醒慢）

维护成本：登录凭证大约一到三个月过期一次，需要重新扫一次码。

> 注意：主流的开源实现已在 2026 年 1 月归档，代码仍可用，但意味着后续可能需要自己修。这是免费方案的固有代价。

### 方式 B：免费受限源

直接用现成的免费转换服务（如 `wechat2rss.xlab.app`），零部署零维护，但**只能订阅它已收录的约 300-400 个公众号**，以技术、安全、AI、财经领域为主。列表外的号加不进去。延迟约 6 小时。

适合：你的目标号正好在收录列表里，或者只想先试试效果。

### 方式 C：付费聚合服务

约 150 元/年起，可订阅任意公众号，由服务商承担反爬维护。最省事、最稳定，把唯一的麻烦外包出去。

适合：公众号是你的主要信息源，且不想操心维护。

## 四、AI 摘要

配置了 `LLM_API_KEY` 后，每条内容会附一句不超过 40 字的结论。摘要失败（没配 Key、超时、额度用完）只会降级成"标题 + 链接"，**绝不会导致推送失败**。

省钱：每次运行默认只对前 20 条做摘要（`max_summary_per_run`），一天两次约 40 条，成本极低。

想换服务商，改 `LLM_BASE_URL` 和 `LLM_MODEL` 即可，任何 OpenAI 兼容接口都能用。

## 六、日常维护

基本没有。只有两种情况需要你动手：

1. **新增/停用信息源**：改 `config/sources.yaml`，提交即可，下次运行生效
2. **微信通道重新登录**：约一到三个月一次，程序会主动推消息告诉你

源健康是自动监控的：某个源连续 3 次抓取失败，会单独推一条告警告诉你它坏了，而不是让你以为"今天没更新"。

## 七、已知局限（请务必知道）

1. **GitHub 定时会延迟**：高峰期可能晚几十分钟，极偶尔会跳过一次。不适合需要精确到分钟的场景。
2. **微信公众号不存在"完全免费且长期稳定"的方案**。这是微信反爬机制决定的，不是本项目的缺陷。选方式 C 可以规避，选 A/B 就要接受偶尔需要修。
3. **网页抓取会随目标站改版而失效**。程序会告警，但修复需要你重新抓一次选择器。
4. **历史文章抓不到**：只能获取最近发布的内容，无法回溯。

## 八、常见问题

**Q：手动跑了一次，群里没收到消息？**
A：先看 Actions 日志。如果显示"无新增内容，本次静默"，说明源抓到了但都在最近已推送记录里——这是正常的去重行为。想强制测试，把 `data/state.json` 里的 `sent` 清空成 `{}` 再跑一次。

**Q：日志里全是"采集 失败"？**
A：多半是 `sources.yaml` 里的地址或选择器不对。把那个源的 `enabled` 改成 `false`，单独调试。

**Q：状态文件会不会把仓库撑爆？**
A：不会。程序只保留最近 30 天的推送记录，超出自动清理。

**Q：能不能改成每天一次 / 三次？**
A：改 `.github/workflows/daily.yml` 里的 `cron` 行。记住填的是 UTC 时间，北京时间减 8 小时。例如北京时间 09:00 写 `0 1 * * *`。

**隐私**：如果你的源清单不想公开，把仓库设为私有；或者把 `sources.yaml` 里的地址写成 `${MY_FEED_1}`，然后在 Secrets 里添加 `MY_FEED_1` 填上真实地址，程序启动时会自动替换。
